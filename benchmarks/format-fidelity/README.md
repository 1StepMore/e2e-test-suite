# Format-Fidelity Benchmark (Omni vs pandoc)

Measures how well the Omni Suite pipeline **preserves document structure**
(paragraphs / tables / images) when round-tripping a `.docx`, compared against
a plain **pandoc direct** conversion. This is a *format-fidelity* benchmark:
it counts structure, not translation quality.

## The 3 comparison paths

| Path | What happens | Purpose |
|------|--------------|---------|
| **source baseline** | The input `.docx` itself, counted as-is. | Ground truth all outputs are compared against. |
| **Omni MD path** | `opp extract --target-format md` → `ol translate-md` (FAKE_LLM) → `orf apply-md --target-format docx`. | The production MD route: extract → translate → backfill. |
| **pandoc direct** | `pandoc input.docx -o output.docx` (docx → docx). | Best-effort baseline: what a generic converter alone preserves. |

## Fixtures

- `fixtures/plain.docx` — byte-for-byte copy of `tests/production/small_fixture.docx`
  (the standard hermetic test document).
- `fixtures/rich.docx` — generated by `make_rich_fixture.py` (python-docx).
  Contains **≥ 1 table, ≥ 1 inline image (a 1×1 px PNG embedded inline in the
  generator script), ≥ 1 built-in named paragraph style (`Heading 1`) and ≥ 1
  custom style (`Benchmark Callout`)**. The generator is self-contained
  (the PNG is base64-embedded) and idempotent — re-running it overwrites the
  same output deterministically.

## Metric definitions (one consistent method per metric)

Counts are taken from the OOXML payload (`word/document.xml` + `word/media/`)
via Python `zipfile`, applied **identically** to source and both outputs:

| Metric | Method |
|--------|--------|
| `paragraphs` | regex count of paragraph block open tags `<w:p>` / `<w:p …>` in `word/document.xml` |
| `tables` | regex count of `<w:tbl>` / `<w:tbl …>` in `word/document.xml` |
| `images` | number of files under `word/media/` inside the `.docx` zip |

Images are counted as embedded media files (not `<w:drawing>` elements), so a
re-used image stored once still counts once — this is the stable, converter-
independent signal.

### Preservation rate

For each output path and metric:

```
preservation_rate = count(path output) / count(source)
```

`1.0` means perfect structural preservation for that metric; `< 1.0` means the
path dropped structures (e.g. a table flattened into paragraphs); `> 1.0`
usually means the path split blocks (e.g. one source paragraph split into
several). Rates are printed per run; `metrics.json` carries the raw counts so
rates can be recomputed for any pair.

## Style axis: why it is `N/A` in this run

`metrics.json` reports `"style_axis": "N/A — …"`. Reason: the benchmark runs
the **MD path**, where OPP extracts to Markdown and ORF re-renders through
pandoc — Markdown does not carry source DOCX styles through by construction,
so a style comparison would measure the format, not the tool. The **XLIFF
path** (`opp --target-format xlf` → `orf apply-xliff`) is the style-fidelity
route; measuring it is an planned extension of this harness, not part of this
run.

## Reproduction

```bash
source /mnt/d/贯维/Omni_Suite/.venv_ol/bin/activate

# 1. (Re)generate the rich fixture (idempotent)
python benchmarks/format-fidelity/make_rich_fixture.py

# 2. Run the benchmark (default input: fixtures/plain.docx)
bash benchmarks/format-fidelity/run_benchmark.sh

# 3. Or against the rich fixture
bash benchmarks/format-fidelity/run_benchmark.sh \
    benchmarks/format-fidelity/fixtures/rich.docx
```

The script sets `OMNI_TEST_FAKE_LLM=1` and
`OL_CONFIG_PATH=Omni_Localizer/config/test_universal.yaml` itself and resolves
all paths relative to its own location, so it works from any CWD. Results land
in `benchmarks/results/<ts>/` (git-ignored, at the `benchmarks/` level — one
level above this README):

- `metrics.json` — counts + status per path (see below)
- `omni_output.docx` / `pandoc_output.docx` — the produced documents
- `omni/opp/`, `omni/ol/` — intermediate MD/XLIFF artifacts for debugging

If **pandoc is missing or fails**, path (b) is skipped with a clear stderr
message and recorded as `"status": "skipped"|"error"` in `metrics.json`; the
Omni path (a) still runs. A missing input file is a hard error (non-zero exit,
message on stderr).


## FAKE_LLM disclaimer (important)

The translation step runs with `OMNI_TEST_FAKE_LLM=1`: OL substitutes
placeholder "translations" instead of calling a real LLM. **This benchmark
therefore measures FORMAT fidelity — how much document structure each path
preserves — not translation quality.** Run it with real API keys (unset the
env var in `run_benchmark.sh`) only if you also want to eyeball the translated
text; the structural metrics are identical either way.
